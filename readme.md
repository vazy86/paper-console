# PC-1 (Paper Console 1)

**Небольшой автономный термопринтер для новостей, погоды, головоломок, электронной почты и многого другого.**

---

* **Без экранов:** результат печатается на настоящей термобумаге.
* **Без подписок:** используются принадлежащие пользователю API-ключи или локальные алгоритмы.
* **Качественные материалы:** ореховое дерево, латунь и архивная бумага.
* **Универсальные каналы:** полностью настраиваемые каналы (Adventure, Astronomy, Calendar, Email, History, Journal Prompt, Maze, News, Print Endpoint, QR Code, Quotes, RSS, Sudoku, System Monitor, Text / Note, Weather, Webhook)

Дополнительная информация и фотографии сборки доступны на странице [travismiller.design/paper-console](https://travismiller.design/paper-console).

![Вид PC-1 спереди](images/pc-1_front2.jpg)
*Вид спереди: латунный поворотный переключатель, кнопка и выход термобумаги*

## 1. Быстрый запуск (программное обеспечение)

Всю систему можно запустить на компьютере без оборудования, чтобы проверить логику и увидеть вывод «принтера» в терминале.
Для команд проекта используйте Unix-подобную оболочку: Linux, macOS или WSL в Windows.

**Бэкенд:**

```bash
./run.sh

# Или запустите напрямую
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

* **Документация API:**
  * Локально: [http://localhost:8000/docs](http://localhost:8000/docs)
* **Тестовый вывод:** следите за окном терминала. «Принтер» выводит текст туда.

**Фронтенд (интерфейс настроек):**
```bash
cd web
npm install
npm run dev
```
* **URL:** [http://localhost:5173](http://localhost:5173)

**Тесты:**
```bash
./testing/run_tests.sh
```

### Распаковка и первое использование

Когда пользователь распаковывает PC-1 и впервые включает его, ожидается следующий порядок действий:

1. **При первом запуске печатается чек с инструкцией по настройке**
   - Принтер автоматически печатает инструкции по первоначальной настройке.
   - В них указаны:
     - SSID сети настройки: `PC-1-Setup-XXXX` (суффикс уникален для устройства)
     - пароль устройства (общий для Wi-Fi настройки, входа в параметры, напечатанных инструкций и SSH)
     - QR-код Wi-Fi для быстрого подключения телефона к сети настройки
     - адрес настройки: `http://10.42.0.1` (а также `http://pc-1.local`)

2. **Пользователь подключается к Wi-Fi сети настройки**
   - На телефоне или компьютере отсканируйте напечатанный QR-код Wi-Fi либо подключитесь к указанному SSID вручную.
   - При ручном подключении введите напечатанный пароль устройства.
   - На многих телефонах и ноутбуках после подключения страница настройки должна открыться автоматически как captive portal.

3. **Пользователь настраивает домашний Wi-Fi через веб-интерфейс**
   - Если страница настройки не открылась автоматически, перейдите на `http://10.42.0.1`.
   - Выберите домашнюю сеть и введите пароль.
   - Интерфейс предупреждает, что соединение может прерваться, пока PC-1 переключается между сетями.

4. **PC-1 подключается к домашнему Wi-Fi**
   - Устройство пытается установить соединение в фоновом режиме.
   - После успешного подключения PC-1 печатает чек с подтверждением.
   - Пользователь снова подключает телефон или компьютер к домашнему Wi-Fi.

5. **Пользователь открывает настройки**
   - Перейдите на `http://pc-1.local`.
   - Настройте каналы, модули и параметры печати.

6. **Обычное ежедневное использование**
   - Поверните переключатель, чтобы выбрать канал (1–8).
   - Нажмите кнопку, чтобы распечатать выбранный канал.
   - Удерживайте кнопку около 5 секунд (при достижении порога появится подсказка в виде половины строки бумаги), затем отпустите её, чтобы открыть **Quick Actions**:
     - `1` Table of Contents
     - `2` System Monitor
     - `3` Reprint Setup Instructions
     - `4` Reset WiFi
     - `5` Reset Factory Settings
     - `8` Cancel
   - Quick Actions выполняются однократно: после выбора пункта меню автоматически закрывается.
   - Если в течение 2 минут ничего не выбрать, Quick Actions автоматически закроется и напечатает сообщение о тайм-ауте.
   - Удерживайте кнопку около 15 секунд для **Factory Reset** (настройки очищаются, устройство перезагружается).
   - Веб-интерфейс можно в любое время использовать для изменения модулей, расписаний и системных настроек.

Если настройка Wi-Fi завершится неудачно, PC-1 вернётся в режим настройки, чтобы пользователь мог повторить попытку.

## 2. Установка программного обеспечения

### Среда разработки

Команды проекта предполагают Unix-подобную оболочку. В Windows используйте WSL.

Первоначальная настройка:

```bash
python3 -m venv .venv
./.venv/bin/python -m pip install -r requirements-dev.txt
cd web && npm install
```

1. **Установите зависимости Python:**
   ```bash
   ./.venv/bin/python -m pip install -r requirements-dev.txt
   ```
   Будут установлены зависимости приложения и инструменты тестирования. Пакеты GPIO, предназначенные только для Raspberry Pi, намеренно исключены.

2. **Запустите сервер:**
   ```bash
   ./run.sh
   # Или: uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
   ```

### Docker (только программное обеспечение / тестовый принтер)

Если вы хотите запустить PC-1 без Raspberry Pi, приложение также можно запустить в Docker и использовать для тестирования встроенный вывод тестового «принтера» в терминал.

1. **Создайте `Dockerfile` в корне репозитория:**
   ```Dockerfile
   FROM python:3.12-bookworm

   WORKDIR /paper-console

   COPY . .

   RUN apt update && apt install -y sudo npm nodejs network-manager

   RUN pip install Pillow
   RUN pip install fastapi uvicorn[standard] pydantic requests
   RUN pip install feedparser icalendar pytz python-dateutil astral beautifulsoup4
   RUN pip install pytest

   RUN python3 -m venv .venv; ./.venv/bin/python -m pip install -r requirements-dev.txt

   ENTRYPOINT ["./run.sh"]
   ```

2. **Соберите образ:**
   ```bash
   docker buildx build -t local/pc-1 .
   ```

3. **Запустите контейнер:**
   ```bash
   docker run --rm -it -p 8000:8000 local/pc-1
   ```

4. **Откройте приложение:**
   Перейдите в браузере на `http://localhost:8000`.

5. **Найдите пароль устройства:**
   Проверьте журналы контейнера и найдите напечатанные инструкции по настройке, особенно раздел `STEP 1: CONNECT TO WIFI`.

6. **Используйте тестовый принтер:**
   При печати канала из веб-интерфейса результат появляется в терминале, где запущен контейнер.

### Развёртывание на Raspberry Pi

1. **Установите зависимости Python:**
   ```bash
   ./.venv/bin/python -m pip install -r requirements-pi.txt
   ```

2. **Запустите скрипт настройки:**
   ```bash
   cd ~/paper-console
   chmod +x scripts/setup_pi.sh
   sudo scripts/setup_pi.sh
   ```
   Скрипт выполнит следующие действия:
   - задаст имя хоста (по умолчанию `pc-1`);
   - установит Nginx (веб-прокси) и Avahi (mDNS);
   - настроит службу systemd;
   - добавит пользователя в группу `lp` для доступа к принтеру.

3. **Откройте устройство:**
   Перейдите в браузере на `http://pc-1.local` (либо на выбранное вами имя хоста).

## 3. Настройка

Настройка полностью выполняется через **веб-интерфейс** по адресу `http://pc-1.local` (или `http://localhost:8000`).

### Общие настройки
* **Местоположение:** название города, широта, долгота и часовой пояс (с функцией поиска).
* **Формат времени:** 12-часовой (AM/PM) или 24-часовой формат.

### Система каналов
* **8 положений каналов:** каждое положение (1–8) соответствует позиции поворотного переключателя.
* **Модульная система:** каналы являются контейнерами. Одному каналу можно назначить **несколько модулей** (например, сначала News, затем Weather, затем Sudoku).
* **Изменение порядка:**
  * **Каналы:** стрелки вверх/вниз рядом с заголовком канала меняют местами каналы целиком.
  * **Модули:** кнопки со стрелками внутри карточки канала изменяют порядок печати.
* **Печать по расписанию:** нажмите значок часов на любом канале, чтобы настроить автоматическую печать в определённое время.

### Типы модулей

Каждый модуль является независимым экземпляром со своей конфигурацией. Подробности см. в разделе [Архитектура и модули](#4-архитектура-и-модули).

Доступные модули: **News API**, **RSS Feeds**, **Weather**, **Email Inbox**, **Sudoku**, **Maze**, **Adventure**, **Astronomy**, **Calendar**, **Webhook**, **Print Endpoint**, **QR Code**, **Text / Note**, **Quotes**, **Journal Prompt**, **History**, **System Monitor**, **Word of the Day**.

### Хранение настроек
* **Файл настроек:** `config.json` (сохраняется автоматически и исключён из Git).
* **Сброс:** кнопка "Reset All Settings" восстанавливает заводские настройки.

### API состояния принтера

Клиенты webhook могут опрашивать `GET /api/printer/status` без аутентификации. Возвращается
`{"ready": true, "reason": "idle"}`, когда драйвер принтера доступен и ни печать, ни удержание кнопки не зарезервировали его. В остальных случаях `ready` имеет значение `false`, а поле
`reason` — `printing`, `hold` или `unavailable` (включая ожидающую перезагрузку UART принтера).

Это справочный снимок готовности приложения. Он не опрашивает физический принтер, не обнаруживает отсутствие бумаги или питания и не резервирует следующее задание. Принтер остаётся занятым до завершения печати либо очистки после отмены. Клиенты всё равно должны обрабатывать ответ HTTP
`423` от webhook печати, если другое задание запустилось до получения их запроса, а также ошибки аутентификации и проверки содержимого конечной точки.

### Локальные процессы проверки
Для разработки без Raspberry Pi используйте локальные процессы тестирования и создания снимков:

* **Pytest:** `./testing/run_tests.sh`
* **Снимки печати:** `./.venv/bin/python testing/render_all_prints.py --output-dir testing/artifacts/print`
* **Снимки интерфейса настроек:** `./.venv/bin/python testing/render_settings_ui.py --output-dir testing/artifacts/ui`

Эти процессы используют тестовые или локальные пути и не требуют GPIO-пакетов Raspberry Pi.

### Переменные окружения безопасности и сети
Для производственного развёртывания настройте следующие переменные окружения:

* **`PC1_DEVICE_PASSWORD`**: необязательная замена общего пароля устройства, который используется для Wi-Fi настройки, входа в параметры, напечатанных инструкций и SSH.\
  На управляемых устройствах PC-1 рабочий пароль обычно хранится в файле учётных данных под управлением устройства. Для скриптового доступа клиенты могут передавать заголовок `X-PC1-Device-Password`.
* **Сеансы входа в настройки:** веб-интерфейс может запомнить браузер с помощью подписанного cookie сеанса `HttpOnly`, чтобы пользователю не приходилось вводить пароль при каждом посещении.
* **`PC1_CORS_ORIGINS`**: разделённые запятыми источники CORS (по умолчанию разрешены только локальные источники и источники разработки).
* **`PC1_UPDATE_GITHUB_REPO`**: идентификатор репозитория GitHub, используемый для проверки и установки OTA-обновлений (по умолчанию `travmiller/paper-console`).
* **`PC1_UPDATE_TARBALL_SHA256`**: необязательная ожидаемая контрольная сумма SHA256 архива OTA.
* **`PC1_LOG_LEVEL`**: уровень журналирования бэкенда (по умолчанию `WARNING` в сборках для устройства).
* **`UVICORN_LOG_LEVEL`**: уровень журналирования Uvicorn для `run.sh` (по умолчанию `warning`).
* **`UVICORN_ACCESS_LOG`**: установите `1`, чтобы включить журналы HTTP-доступа (по умолчанию `0` для уменьшения объёма журналов).

### Артефакты производственного выпуска

Чтобы собрать версионированные артефакты выпуска для производственных устройств без Git, выполните:

```bash
./.venv/bin/python scripts/release_build.py --version v1.2.3 --build-web
```

Устройства могут получать бета-версии OTA через **General Settings → Updates → Beta Releases**.
Текущие пути стабильных и бета-выпусков, включая процесс публикации GitHub по тегам, рекомендуемые ветки `main` и `beta`, а также рекомендации по исправлениям стабильных OTA-выпусков описаны в `scripts/RELEASE.md`.

### Сведения о модулях

**News API:** главные новости NewsAPI; требуется API-ключ.

**RSS Feeds:** пользовательские URL-адреса RSS; получает и печатает блоки статей с необязательным QR-кодом.

**Weather:** Open-Meteo; использует глобальное местоположение из настроек.

**Email Inbox:** IMAP; настраиваемый интервал опроса; печатает непрочитанные сообщения.

**Sudoku:** уровни Easy / Medium / Hard; созданная головоломка печатается как растровая сетка.

**Maze:** уровни Easy / Medium / Hard; печатаемый лабиринт в виде растрового изображения с отметками начала и конца.

**Adventure:** интерактивное приключение с выбором действий при помощи переключателя и кнопки (печатает части истории, а после завершения возвращается к обычным каналам).

**Astronomy:** восход и закат, фаза Луны, схема движения Солнца; использует глобальное местоположение.

**Calendar:** URL-адреса iCal; представления месяца, недели и дня; повторяющиеся события с учётом часового пояса.

**Webhook:** GET/POST; заголовки, тело запроса и извлечение данных по пути JSON для пользовательских API.

**QR Code:** URL-адреса, Wi-Fi, контакт, телефон, SMS, электронная почта и обычный текст.

**Text / Note:** форматированный текст (TipTap JSON): заголовки, списки, полужирный/курсивный текст и горизонтальные линии.

**Quotes:** офлайн-база из тысяч цитат; при каждой печати выбирается случайная цитата.

**Journal Prompt:** офлайн-библиотека тем для дневника; при каждой печати выбирается случайная тема.

**History:** офлайн-события «в этот день»; в конфигурации можно указать количество событий.

**System Monitor:** имя хоста, IP-адрес, Wi-Fi, индикаторы диска и памяти, время работы, нагрузка и температура процессора (если доступна).

**Word of the Day:** слово дня Merriam Webster.

**Crossword:** уровни Easy / Medium / Hard; созданный кроссворд печатается как растровая сетка.

**Word Search:** уровни Easy / Hard; созданная головоломка с поиском слов печатается как растровая сетка.

## 5. Настройка оборудования

### Необходимые компоненты
1. **Raspberry Pi Zero 2 W** с установленной Raspberry Pi OS Lite
2. **Термопринтер** (QR204/CSN-A2 или совместимый термопринтер 58 мм с TTL-интерфейсом; максимальный диаметр рулона бумаги — 30 мм)
3. **Однополюсный 8-позиционный поворотный переключатель**
4. **Кнопка без фиксации** (1 шт.)
5. **Источник питания:** 5 В, 5 А, с цилиндрическим разъёмом и клеммным адаптером

### Полные таблицы подключения (по группам компонентов)

Подключения разделены на логические группы (блоки), чтобы упростить сборку со стандартными разъёмами DuPont или JST.

#### 1. Блок питания и данных принтера (верхний)
*Используйте блок разъёмов на 4 или 5 контактов.*

| Контакт | GPIO | Назначение | Подключить к |
| :---: | :---: | :--- | :--- |
| **2** | 5V | **Питание (+)** | Внешний БП 5 В (+) |
| **6** | GND | **Питание (-)** | GND внешнего БП (-) |
| **8** | 14 | **TX (данные)** | RX принтера |
| **10** | 15 | **RX (данные)** | TX принтера |
| **12** | 18 | **DTR (управление потоком)** | DTR принтера |
| **14** | GND | **Сигнальная земля** | GND принтера |

#### 2. Блок основной кнопки (средний)
*Используйте 2-контактный разъём.*

| Контакт | GPIO | Назначение | Подключить к |
| :---: | :---: | :--- | :--- |
| **20** | GND | **GND кнопки** | Контакт 1 кнопки |
| **22** | 25 | **Сигнал кнопки** | Контакт 2 кнопки |

#### 3. Блок поворотного переключателя (нижний)
*Используйте 12-контактный блок разъёмов (2x6).*

| Контакт (слева) | GPIO | Назначение | | Контакт (справа) | GPIO | Назначение |
| :---: | :---: | :--- | :--- | :---: | :---: | :--- |
| **29** | 5 | **Положение 1** | \| | **30** | GND | *Не используется* |
| **31** | 6 | **Положение 2** | \| | **32** | 12 | *Не используется* |
| **33** | 13 | **Положение 3** | \| | **34** | GND | *Не используется* |
| **35** | 19 | **Положение 4** | \| | **36** | 16 | **Положение 6** |
| **37** | 26 | **Положение 5** | \| | **38** | 20 | **Положение 7** |
| **39** | GND | **Общий** | \| | **40** | 21 | **Положение 8** |

### Наглядная схема контактов
Обозначения: `[X]` = используется, `[ ]` = свободен. Разъём имеет ширину 2 контакта.

```
      (Контакт 1) [ ] [X] (Контакт 2)  --> Питание 5 В (+)
      (Контакт 3) [ ] [ ] (Контакт 4)
      (Контакт 5) [ ] [X] (Контакт 6)  --> Питание GND (-)
      (Контакт 7) [ ] [X] (Контакт 8)  --> TX принтера
      (Контакт 9) [ ] [X] (Контакт 10) --> RX принтера
     (Контакт 11) [ ] [X] (Контакт 12) --> DTR принтера
     (Контакт 13) [ ] [X] (Контакт 14) --> GND принтера
     (Контакт 15) [ ] [ ] (Контакт 16)
     (Контакт 17) [ ] [ ] (Контакт 18)
     (Контакт 19) [ ] [X] (Контакт 20) --> GND кнопки
     (Контакт 21) [ ] [X] (Контакт 22) --> Сигнал кнопки
     (Контакт 23) [ ] [ ] (Контакт 24)
     (Контакт 25) [ ] [ ] (Контакт 26)
     (Контакт 27) [ ] [ ] (Контакт 28)
     (Контакт 29) [X] [ ] (Контакт 30) --> Переключатель 1
     (Контакт 31) [X] [ ] (Контакт 32) --> Переключатель 2
     (Контакт 33) [X] [ ] (Контакт 34) --> Переключатель 3
     (Контакт 35) [X] [X] (Контакт 36) --> Переключатель 4 | Переключатель 6
     (Контакт 37) [X] [X] (Контакт 38) --> Переключатель 5 | Переключатель 7
     (Контакт 39) [X] [X] (Контакт 40) --> Общий | Переключатель 8
```

### Термопринтер

**Последовательное подключение TTL:**
1. Подключите провода по приведённой выше таблице.
2. **Последовательный порт настраивается автоматически** скриптом `scripts/setup_pi.sh` (консоль отключается, аппаратный порт включается).
3. После настройки устройство доступно как `/dev/serial0`.

### Источник питания

**Рекомендуемая схема (раздельное питание):**
1. **Источник:** используйте блок питания 5 В, 5 А с цилиндрическим разъёмом.
2. **Распределение:** с помощью собственной платы HAT или клеммного разветвителя одновременно подайте питание в две точки:
    * **На Pi:** подключите контакты GPIO 2 (5V) и 6 (GND).
    * **На принтер:** подключите кабель питания принтера.
3. **Предупреждение:** **не** подключайте блок питания к USB-порту Pi и не пытайтесь питать принтер от контактов GPIO платы Pi. Принтер потребляет слишком большой ток (до 4 А), из-за чего Pi будет аварийно отключаться.

## 6. Устранение неполадок

### Проблемы с принтером
* **Устройство не найдено:**
  * Проверьте наличие `/dev/serial0`: `ls -l /dev/serial*`.
  * Если устройство отсутствует, запустите скрипт настройки: `sudo scripts/setup_pi.sh` (он автоматически настраивает последовательный порт).
  * Либо настройте вручную: `sudo raspi-config` → Interface Options → Serial Port → включите аппаратный порт и отключите консоль.
* **Отказано в доступе:**
  * Убедитесь, что пользователь входит в группу `dialout`: `groups`.
  * Добавьте пользователя: `sudo usermod -a -G dialout $USER` (затем выйдите из системы и войдите снова).
* **Ничего не печатается:**
  * Убедитесь, что блок питания обеспечивает достаточный ток (не менее 5 А).
  * Проверьте подключение принтера к правильным контактам GPIO по приведённой выше таблице.
  * Убедитесь, что принтер включён (индикаторы работают ожидаемым образом).
  * Проверьте индикаторы или сообщения об ошибке/состоянии на самом принтере, если они имеются.
  * Проверьте принтер простой командой: `echo "test" > /dev/serial0`.
  * Проверьте журналы службы: `sudo journalctl -u pc-1.service -f`.
  * Убедитесь, что последовательный порт не занят другим приложением (используйте `lsof /dev/serial0`).

### Проблемы со службой
  * **Циклический перезапуск:**
  * Служба использует `run.sh` для автоматической обработки конфликтов портов.
  * Перезапуск: `sudo systemctl restart pc-1.service`.
  * Проверьте журналы: `sudo journalctl -u pc-1.service -f`.
  * **Порт уже используется:**
  * `run.sh` автоматически завершает зависшие процессы.
  * Если проблема сохраняется, перезагрузите устройство: `sudo reboot`.
  * **Хранение журналов:**
  * Скрипт настройки конфигурирует journald для работы в оперативной памяти (`Storage=volatile`) с ограниченным объёмом (`RuntimeMaxUse=16M`).
  * Это уменьшает количество записей на SD-карту и предотвращает длительное накопление журналов на диске.
  * Скрипт также устанавливает `pc1-storage-guard.timer` (запускается каждые 6 часов), который очищает журналы и кэш при увеличении использования корневого раздела.
  * Дампы памяти отключены (`/etc/systemd/coredump.conf.d/pc-1.conf`), чтобы избежать многомегабайтных файлов после сбоев.
  * Текущий объём журналов: `journalctl --disk-usage`.
  * Состояние таймера очистки: `systemctl status pc1-storage-guard.timer`.
  * Немедленный запуск очистки: `sudo systemctl start pc1-storage-guard.service`.
  * Чтобы временно включить более подробное журналирование для диагностики, задайте:
    * `PC1_LOG_LEVEL=INFO`
    * `UVICORN_ACCESS_LOG=1`

### Проблемы отдельных модулей
* **NewsAPI возвращает 0 статей:** проверьте действительность API-ключа и убедитесь, что используется бесплатный тариф.
* **RSS Feeds не работает:** убедитесь, что URL-адреса RSS-лент действительны и доступны.
* **Ошибка аутентификации Email:** используйте **пароль приложения Google**, а не основной пароль. Убедитесь, что включена двухфакторная аутентификация.
* **Calendar не показывает события:** проверьте URL-адрес iCal и наличие событий в выбранном диапазоне дат.
* **Weather показывает неверные данные:** проверьте широту и долготу в `config.json` с помощью поиска местоположения в интерфейсе.
